## Verified live today

**The append-only ledger is not append-only.** Finding 4 of the previous audit, now proven
rather than inferred. Connected as the application's own database user:

```
begin;
update stock_movements set quantity_milli_base = quantity_milli_base + 1 ...;  -- UPDATE 1
delete from stock_movements where seq = (select min(seq) ...);                 -- DELETE 1
rollback;
```

Both succeeded. `\d stock_movements` shows two check constraints and no triggers. The schema
comments and AGENTS.md both describe a database-enforced ledger; the migrations contain no
trigger, rule or privilege grant that enforces it. The application write path is correctly
append-only — this is about the promised safety net underneath it, which is not there. An
accidental `UPDATE` rewrites history while leaving `ingredient_stock.snapshot_seq` unchanged,
so the cache would never notice.

**The deployed container is four weeks stale.** `nomeatnaanfullstackapp-app` was built
**19 August**. Against the running stack on `localhost:8080`, `/recipes`, `/recipes/new`,
`/settings/costing` and every recipe sub-route return **404** — the whole Month 2 costing
module is missing from the image. The same routes return 200 from source. `npm run stack:up`
passes `--build`; a plain `docker compose up -d` does not, and that is what has been running.

**The environment guard works.** `next start` against a `localhost` database was refused with
a clear message rather than started. Worth keeping.

**The low-stock blind spot is latent, not yet biting.** `listLowStock` inner-joins
`ingredient_stock`, and `createIngredient` never writes a cache row, so an ingredient with no
movement cannot appear. Five of the café's 133 ingredients currently have no cache row, but
none of those five has a reorder threshold, so nothing is being hidden today. This changes the
moment the 78 new ingredients land — see below.

**Recipe graph validation still runs outside its transaction.** `saveRecipe` calls
`loadRecipeGraph`, validates units, yield and cycles, and only then opens `db.transaction`.
Two saves interleaved can each pass against the same stale graph and commit a cycle. Confirmed
by reading; not reproduced under real concurrency.

**No login throttling.** No limiter in the action, the database layer or the Caddy config.

## What was fixed, same day

All nine items below were done after the audit above was written. The findings are left
as they were - an audit that quietly edits itself once the work is done stops being a
record of what was wrong.

| # | Fix | Proof |
|---|---|---|
| 1 | Container rebuilt from source | 16 routes on `localhost:8080`, all 200 signed in |
| 2 | `listLowStock` left-joins; never-bought reads "Not yet priced", not ₹0.00 | full suite |
| 3 | `stock_movements` UPDATE/DELETE refused by trigger; runtime role split from the migrator | the probe that succeeded this morning now errors |
| 4 | `saveRecipe` validates and writes in one transaction behind a per-tenant lock | new test fails 3/3 without the lock, passes 3/3 with it |
| 5 | Test rates and batch times cleared, `pizza` removed | rates now blank, awaiting the café's real numbers |
| 6 | Receipts and adjustments refuse a stale pack size; receipt clears after saving | refusal and success both exercised over HTTP |
| 7 | Login throttled per account and per source | 9th wrong password: "Try again in 15 minutes" |
| 8 | `/settings/users` exists; a manager can no longer deactivate or demote an owner | new tests, page renders |
| 9 | `backup.sh` and `restore-check.sh`, documented | a real restore ran: 10 tables, every count matching |

**Migration 0006** makes the ledger append-only at the database. It has one deliberate
escape hatch, `set local app.ledger_maintenance = 'on'`, transaction-local so it cannot
be left switched on. Only `scripts/` and one test fixture use it; the application never
does.

**The runtime role.** `APP_DB_PASSWORD` in the production `.env` makes the migrator create
a `cafe_app` role with data access and no DDL, and the app container runs as that role.
Verified: it reads fine, `create table` and `drop table` are refused, and the ledger
trigger still stops it rewriting history. Two layers, because the trigger protects against
accident and the role protects against the app being compromised.

**Also done, unasked but same defect class:** the receipt form clears after a successful
save (a second click used to duplicate the delivery), `reactivateUser` exists — the
duplicate-email error had been telling people to reactivate an account since Month 1 with
no way to do it — and the 169 accumulated test tenants are gone.

**Deliberately not done:** a server-side idempotency key for receipts. Two clicks on the
same render can still both land. Month 3 needs one for orders; do both there with one
mechanism. Marked in the code.

Tests went from 165 to **177, all passing**. Typecheck and production build both clean.

**One thing I got wrong:** while verifying the stale-pack refusal over HTTP I recorded a
real 2 kg receipt against the café's own tenant instead of a test one. I removed the
movement through the maintenance hatch and rebuilt that ingredient's cache from the
ledger; it is back to 50 kg at ₹42.00/kg, and the tenant is back to its original 134
movements. Nothing else in the café's data was written to.

## What is genuinely good

The arithmetic is the strongest part of the system and it is now proven against a live
database: 165 tests, including the 12 stock paper cases and the 27 costing paper cases, all
passing. Integer paise and milli-base throughout, rounding once at the end of a chain,
sub-recipe rates rounded before a parent consumes them, weighted average that ignores stale
state at zero and negative stock. Missing purchase history raises an explicit error inside
costing rather than quietly becoming zero. Stock writes take a per-ingredient advisory lock.
The cache is a watermark fold over new movements only, and there is a test that the fold and a
full replay agree.

Every screen renders, the navigation covers every page that exists, permissions gate each
link, there is a skip-link, and sign-out is on every page.
